# RFQ surface brief

- **Reviewer disposition:** `ship`. The completed surface is `/request-a-quote/`; it supersedes the Stage 3 RFQ preview/no-send state without claiming that production email delivery is publicly deployed or verified.
- **UI refresh approval and evidence:** The user explicitly approved the homepage and Products UI previews in `.impeccable/review/ui-refresh-preview/` and authorized extending their design rules to the RFQ and remaining routes. The authorized implementation is complete without repeat confirmation. Current RFQ desktop/mobile captures are `.impeccable/review/ui-refresh-result/request-a-quote-1440.png` and `request-a-quote-390.png`; layout and browser records accompany them. They verify the local implementation's UI, not live delivery.
- **Historical Stage 4 verification evidence:** Desktop CUA visual inspection completed. The Astro build completed with 0 errors and 0 warnings; Worker TypeScript passed; Vitest passed 18/18; the Cloudflare deployment dry run succeeded; and a local end-to-end `POST /api/rfq` returned `201` with Wrangler's simulated `send_email` output. No real email was sent. These earlier checks are not current UI-refresh validation.
- **Browser verification caveat:** The in-app browser could not load the third-party Turnstile iframe. The surface responded with the designed explicit load-failure message and visible invalid state rather than hiding the failure or implying that bot protection had passed.
- **Scope and mode:** Operate mode for an industrial buyer starting an inquiry with essential information and optional specifications. Stage 4 validates and attempts delivery of one grouped email; it does not introduce an inquiry database, file upload, attachment storage, account, or CRM workflow.
- **Topology and typography:** H1 `Request a Fan Quote` introduces a compact header with a short reassurance that no model number is needed. Use the shared interior display scale `clamp(44px, 4.5vw, 64px)`, line-height 1, an 18-24ch measure, and 44px mobile H1s. The full form remains the primary column in a two-column desktop workspace; the sticky secondary guidance rail explains field checking, Turnstile verification, the email attempt, and the no-database/no-upload boundary. Remaining factual copy is unchanged.
- **Approved frame and density:** Align header, workspace, and footer to the 1440px content measure; desktop gutters are `max(32px, calc((100vw - 1440px) / 2))` and mobile gutters are 18px. Standard section spacing is 40-64px desktop and 28-40px mobile, with a 32px mobile default; breadcrumb bottom spacing is 24px desktop and 20px mobile. Compact header, workspace, form-heading, and group-transition gaps while retaining readable labels, helpers, errors, and persistent 52px-minimum controls.
- **First-inquiry revision (2026-10-03):** Default groups are reply channels, essential requirements, two optional native `details` disclosures, and submission. The visible data controls are email, WhatsApp, category, estimated quantity, destination and a short summary. One valid reply channel plus category, quantity, destination and summary are required; privacy acknowledgement and bot protection remain mandatory.
- **Optional details:** Technical/delivery details include all existing model, duty, electrical, installation, material and logistics fields. Buyer details include name, company, customer type, country/region and contact preference. All categories can provide technical values. Selection help relies on the required summary and does not require another application answer. Empty optional data remains empty, not an invented buyer profile.
- **Disclosure behavior:** Both groups start collapsed and retain their values when collapsed or when category changes. The selected category updates the technical heading/help without adding required fields. URL audience/category preselection remains available. Native summaries support keyboard activation and explicit focus styling; optional-field errors expand their group before focusing the first invalid control.
- **Validation and states:** Browser and Worker use the same bounded parser. Summary minimum is 10 characters, quantity remains a positive integer up to 1,000,000, and provided optional values still validate. Pending and failure states retain entries; submission locks duplicates. After email-service acceptance, blocked storage/navigation leaves the confirmed success/reference on the form; otherwise the confirmation page uses the tab-local marker.
- **Current verification (2026-10-03):** 26 Astro files with zero diagnostics, 14 built pages, 95 RFQ tests, 13 build-script tests, and Worker/Wrangler type checks passed. Local Edge checked collapsed/expanded layouts at 320, 390, 768 and 1440px (8 combinations) without overflow, duplicate IDs, unnamed controls or field heights under 52px. Delivery failure never becomes a success state, and the form preserves the buyer's entries for correction or retry.
